## 用户可见变化（一句）

侧栏任务卡在 Mission / 计划下方固定一行 **Health**；暂停 / 中断 / 需要你 / 失败 / 完成时，**不得**再出现「思考中…」与循环 shimmer。

## Done（可证伪）

1. When I 暂停运行中任务 → I see Health「已暂停」，且无「思考中…」/ shimmer。
2. When I 任务为 interrupted / waiting_user / failed → Health 分别为可辨文案（已暂停 / 需要你… / 未完成…），仍无运行动画。
3. When I 继续回到 running → Health 为「正常推进」（或「执行中」临时等价），可与计划并存。
4. 单测：`task-progress-view` 断言 `health` 存在且状态映射正确；`ui-acceptance` 要求存在 `task-progress-health`，删除「禁止 health」断言。

## 不做

- 逐步审批 / 批准一次（004）
- 改 background executor 策略
- 完整七层 IA 重排、通用 planner 重构、飞书 4 Gate、composer 旁侧控制（后续切片）
- Notion 全量 token 补齐（S1 只用现有 color + 新增 health 行样式；type ladder 可下一切片）

## Health 文案映射（最小）

| state | 用户文案 |
|-------|----------|
| advancing | 正常推进 |
| recovering | 这条路未成功，正在换一种方式（S1 可暂不触发，缺数据则不硬编） |
| slow | 一段时间没有新进展（S1 可选，有 lastMeaningfulProgressAt 再开） |
| needs_user | 需要你…（登录/验证等） |
| paused | 已暂停 |
| failed | 未完成，并说明缺口若已有 |
| complete | 已验证完成 |

S1 最低：`running→advancing`，`paused|interrupted→paused`，`waiting_user|inputs_required→needs_user`，`failed|cancelled→failed`，`completed→complete`。

## 视觉（Notion 对齐，不扩 scope）

- 状态必须有**文字**（不要只靠色点）— Notion「Don't rely on color alone」
- Health 固定在 Mission 下 — 状态位置固定
- 用现有 `--chijie-muted` / accent / warning / danger；禁止引入 Liquid Glass、大阴影
- 去掉无限 shimmer；短状态变化即可
