# 023-LR-01 当前能力与缺口审计

日期：2026-08-11  
基线：当前 `main` 工作区；保留既有未提交修复，不把构建产物当产品证据。  
验收来源：`docs/product/023-living-reader-research-decision-benchmark.md`

## 结论

当前持节能完成短至中等长度的浏览器任务，但不能可靠完成 `023-LR-01`。决定性缺口不是模型，而是没有持久证据空间、研究配额调度和针对最终交付的确定性验收。

## 真实缺口

| 优先级 | 缺口 | 代码事实 | 对 023 的影响 |
|---|---|---|---|
| P0 | 没有证据空间 / 证据记录 | TaskSnapshot 只有 completion evidence；全仓无 `EvidenceSpace`、来源记录、stance、confidence、dedupe key | G23-2/3/4/7 无法成立；80/30 只能靠模型记忆，数量不可相信 |
| P0 | 没有研究配额调度 | control loop 默认最多 100 steps，且 control 每 step 一个动作；`max_steps` 直接失败 | 打开、阅读并记录 80+30 个对象必然超出单循环；无法自动分批继续 |
| P0 | 没有持久研究队列和检查点 | MissionPlan 只保存最多 12 个短标题与状态；无 query/source queue、processed/failed/retry 状态 | 中断后无法知道下一条来源是什么；容易重复或漏读 |
| P0 | Artifact 不持久 | TaskArtifact 只随 `candidate_complete` 进入 verifier，TaskSession 不保存 artifact 内容 | 长任务中间表格无法作为下一阶段可靠输入；重启后丢失 |
| P0 | 验收器不理解 023 | Artifact verifier 只校验存在、包含、schema、row count、source count；无 80/30 独立计数、反证、2+1+1、恰好三项、飞书回读规则 | 可能生成漂亮报告但仍虚假完成 |
| P1 | 当前打开标签未进入模型观察 | BrowserContext 可枚举 tabs，但 ObservationFrame 只包含当前 tab | 无法自主发现用户已经打开的 Living Reader PDF、文档和设计稿 |
| P1 | 没有 GitHub 项目读取适配层 | 无 GitHub API/repository/issues/commits 能力；只有通用网页动作 | 只能逐页点 GitHub，完整读取慢且容易遗漏；无法稳定记录 HEAD 与对象范围 |
| P1 | 没有飞书交付协议 | 无 Feishu/Lark 专用动作或 adapter；只有通用点击与输入 | 可以尝试操作 UI，但无法稳定建表、批量写记录、回读字段与计数 |
| P1 | 来源失败策略只在模型层 | loop 有通用 action retry/no-progress，但无按来源记录 blocked/alternate/replaced | 单站失败后是否换路径不可审计，恢复后可能重复失败 |
| P1 | 证据内容没有独立质量门 | 当前 completion evidence 是页面状态，不是研究证据的原始依据与推断分离 | 无法阻止搜索摘要、营销文案或无正文来源被计入 |

## 最短实现顺序

1. **证据空间 v1**：持久 EvidenceRecord、批量写入、规范化去重、用户讨论/产品独立计数、进度摘要。
2. **研究任务 checkpoint v1**：阶段配额、query/source queue、processed/failed 状态；每个 control loop 只执行一个可恢复 work cycle。
3. **上下文读取 v1**：把当前 tabs 暴露给模型；增加 GitHub 仓库/Issue/提交的确定性读取路径。
4. **G23 Verifier**：验证 80/30、来源有效性、反证、2+1+1、恰好三个能力和七问覆盖。
5. **飞书交付 v1**：表格批量写入、文档写入、重新读取、URL 与字段/计数回执。
6. 用真实 MiniMax-M3 从空任务运行 `023-LR-01`，只以 G23-1..8 和飞书可见结果为完成。

## 第一实现切片的成功标准

- 同一 task 的证据记录在 MV3 service worker 重启后仍存在。
- 同一 dedupe key 重放不会增加记录数。
- 用户讨论与产品分别计数；搜索摘要和无来源记录不能写入。
- 一次动作可以批量写入同一页面上的多条独立记录。
- 模型每轮能读取当前进度与缺口，而不把全部证据重新塞回上下文。
