# 004 — 任务内自主执行

## 状态

已决定，Owner 于 2026-08-02 确认。旧方向中的“外部提交必须先弹一次批准”不再作为产品默认体验。

## 决策

持节默认在用户给出的任务范围内自主执行。用户说“发邮件”，提交邮件就是任务的一部分；用户说“买”，符合目标的支付流程也不再逐次打断。

- 任务内的导航、读取、填写、媒体控制、提交、发送、购买均不再要求模态批准。
- `external_commit` 仍保留为风险/审计标签，用于完成回执、失败恢复和隐私脱敏，但不再是阻塞点。
- 只有在 Agent 准备执行任务目标明显未包含的高风险动作时，才需要停下来向用户说明。
- 用户可随时用“停止”中止任务；停止是用户掌控手段，不是每步批准。

## 原因

- 长程复杂任务的核心体验是“把目标交出去，等它完成”，不是反复被打断。
- 用户既然已经用自然语言提出任务，任务内的不可逆动作已经获得任务级授权。
- 频繁批准会破坏长任务的连续性，也会让 Agent 看起来不像真正的执行者。

## 放弃的方案

### 每个外部提交前强制一次批准

这是旧方向的核心约束。它能减少误提交，但把用户放在“每个动作都要确认”的监督位，无法承载长程自主执行。

### 用“动作类型”无差别拦截

即使只在提交/发送/购买时拦截，也不能区分“用户明确要求发送”和“Agent 擅自发送”。任务级授权比动作级拦截更符合用户意图。

## 后果

- ActionDispatcher 对外部提交直接执行，不再等待 `approval`。
- 设置页和任务 UI 已删除“审批”作为主流程。
- 旧的审批状态机、审批命令、审批 UI 和旧 SPEC 已删除。
- 安全边界变为：任务目标隐含授权 + 敏感输入直接拦截 + 超范围高风险动作说明。
