# 021 — 长程任务 Agent 北极星

## 状态

**current，Owner 已确认。** 本文件取代旧的“浏览器操作演示 + 强制审批”叙事。旧方向保留为历史文档，不再作为当前北极星。

## 一句话

持节是一个运行在用户 Chrome 里的**长程任务 Agent**：用户交出一个自然语言目标，Agent 自己拆计划、跨页面/站点执行、记住上下文；用户始终看得懂任务进行到哪里、是否健康、何时需要介入，并最终得到可验证交付。

## 用户要看到的效果

1. 用户只给一次任务，例如“调研 10 家竞品，输出对比表和一份结论”。
2. Agent 先给出简短计划，然后开始自主执行。
3. 执行过程中，侧栏持续展示稳定目标、当前阶段、真实进度、当前动作的目的、已找到的关键结果、运行健康度与下一步；不要求用户逐动作确认，也不把工具调用流水账当作进度。
4. 任务完成后给出可检查的成果：表格、报告、文件、页面状态或回执。
5. 用户随时可以暂停、继续、追问、修正或停止；用户干预是连续控制，不是每一步批准。

## 能力定义

### 长程

- 任务可能跨多个页面、多个站点、多轮观察，长度以“目标完成”为准，不以单页面操作为边界。
- 必须有持久化计划：阶段、子目标、检查点、验收条件。
- 中断后应能从计划中恢复，而不是从零开始。

### 复杂

- 需要多步推理、信息收集、结果整理和交付物生成。
- 不是“打开某个页面”或“暂停视频”这类单动作捷径。
- 单动作捷径可以作为内部工具，但不是产品核心。

### 自主

- 任务级授权：用户提出目标即授权目标内的行动。
- 不弹强制批准，不因“外部提交”打断。
- 超范围高风险动作才说明；敏感输入仍直接拒绝自动处理。

### 可验证

- 中间检查点和最终结果都必须有可观察证据。
- 模型说“完成”不算完成；证据不足时诚实失败。

### 可理解、可干预

- 侧栏不是聊天记录或调试日志，而是长程任务的实时控制台。
- 用户应在几秒内回答：目标是什么、进行到哪一步、现在做什么、运行是否健康、已经得到什么、是否需要我介入。
- 有明确总量时展示持久化计数或验收门；没有可信总量时不伪造百分比。
- 当前动作必须说明服务于哪个阶段或验收门；原始 action、selector、digest、模型思维过程只进入折叠审计层。
- 暂停、等待用户和失败必须与“正在执行”视觉互斥，禁止展示陈旧活动造成假运行感。

## 当前缺口

1. 上下文压缩仍是确定性 archive，不是 LLM 语义摘要。
2. 跨中断的完整任务恢复协议仍偏薄（plan 持久化有了，恢复体验未封顶）。
3. 真站长尾（飞书/B 站等）仍需 Owner 登录态；与旧 M3 黄金旅程相关，**不是**当前北极星本身。
4. 外环 Skill 候选需先通过当前 evaluator 红队、冻结回归与 Owner native acceptance，在此之前不得晋升。
5. 现有侧栏仍以目标原文、启发式阶段和动作数量为主，尚不能稳定表达真实验收门、运行健康度、阶段成果和下一步。
6. 新证据协议的 committed `eval:build` → `RUNS=3` matrix → task-specific gate 尚待在干净 SHA 上正式复跑。
