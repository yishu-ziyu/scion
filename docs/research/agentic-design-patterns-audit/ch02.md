# 第 2 章：路由（Routing）

## 书里的机制
- 先分析用户那一句，再按意图把它送到不同后续，而不是固定一条线做完（「分析用户的查询」「基于其**意图**路由查询」）。
- 意图对应不同处理：查订单、查产品、技术支持；说不清就去澄清（「如果意图不清楚，路由到澄清子智能体或提示词链」）。
- 路由可以发生在任务开头分类、链中间选下一步、或从一组工具里选一个（「在开始时应用以对主要任务进行分类，在处理链内的中间点应用」）。
- 实现方式一：提示语言模型，只输出类别标识，再按这个标识走分支（「基于 LLM 的路由」「只输出一个词：'booker'、'info' 或 'unclear'」）。
- 实现方式二：关键词、模式、if-else / switch 的预定规则（「基于规则的路由」）。
- 实现方式三：查询做成向量，和各条路由的向量比相似度（「基于嵌入的路由」）。
- 实现方式四：单独训练的分类器在推理时做决定，不是生成模型当场写类别（「决策组件不是在推理时执行提示词的生成模型」）。
- 示例结构是协调器把请求委托给专门处理函数（预订 / 信息 / 不清楚），而不是一个处理函数包打（「将用户请求路由到不同的模拟"子智能体"处理程序」「RunnableBranch」）。

## 结论
- 部分做成
- 完成度：63
- 一句话：`TaskManager.classifyStartOrFollowUp` 已把 `decideUserTurn` / `resolveUserTurnCheap` 接到 `TaskManager.dispatch`，用户那句会进 reply / clarify / execute / stop；但 execute 之后没有按意图分到预订/问答这类专门处理函数，`deriveInstructionDeliverableContract` 故意不从那句话派生任务类型，且搜过 `embedding` / `sub_agents` / `RunnableBranch` 无路由命中。

## 对持节业务的意义
用户在侧栏交出一句话时，真正分路的是 `TaskManager.dispatch`，不是侧栏自己猜。
说「你好」或「谢谢」时，侧栏只多一句招呼，当前标签页不会被开走、也不会出现一条 `running` 任务。
说「打开… / 搜索…」或点「再说一次」且分类为 execute 时，侧栏开始按发生的事往下长，结果仍要能在页上核对。
正在做的时候说「停止」，侧栏出现「好的，已停止。」，任务变成 `cancelled`，页面操作停住。
说不清时失败是：没有结果可核对，只有一句追问；模型 JSON 坏掉时同样停在这句话，不会假装已经动手。
循环里的 skill 分路用户几乎看不见：原子填表可能突然变得很准，长任务则一直走同一条观察-动作循环；对不上书里「交给专门子智能体」那种可点名的分发。

## 完成方案
- Goal: 保持 `TaskManager.dispatch` 作为唯一入口分类；把已经存在的 `discoverSkills` → `SkillRuntime.tryDecide` 分路写进侧栏时间线（skill 名 + 是否回落到循环），不新开协调器或第二套 agent。
- Hard bar:（when I do X, I see Y）当我在侧栏发送「你好」，我看见「你好，需要我帮你在页面上做什么？」且没有新任务；当我发送一条能命中 `formFillSubmitSkill.match` 的短填表指令，我看见带 `builtin.form-fill-submit` 的一步而不是只有泛化思考；当我发送带「然后…接着…」的长指令，我看不见 skill 抢步。
- 改哪些现有文件（不要新开第二套 agent 树）
  - `chrome-extension/src/background/agent/backends/control-llm.ts`：`skillTry` 已有 `skill.discover` / `skill.run` span，把选中的 `skillId` / `fallbackUsed` 经现有 `hooks` / 事件送到侧栏，不另起总线。
  - `pages/side-panel/src/SidePanel.tsx`（以及已有 attempt / event 展示）：只渲染这条记录，不在侧栏做分类。
  - 若原子 skill 漏匹配：只改对应 `chrome-extension/src/background/agent/skills/builtin/*.ts` 的 `match`，不动 `classifyStartOrFollowUp`。
- 非目标:
  - 不引入 LangGraph / ADK `sub_agents` / `RunnableBranch`。
  - 不按书里的预订/信息/工单去拆专门子智能体。
  - 不做嵌入路由或监督分类器。
  - 不把分类搬到 `SidePanel.tsx`。
  - 不复活 `planner.ts` / `navigator.ts` 当生产分类器（`factory.ts` 生产默认是 `createLlmControlDriver`）。
  - 不推翻 Decision 005、不为凑章从那句话派生任务类型。
