# 第 10 章：模型上下文协议（Model Context Protocol (MCP)）

## 书里的机制
- MCP 是一份开放标准，用来统一大模型和外部程序、数据、工具怎么说话。（「作为开放标准，旨在标准化 Gemini、OpenAI 的 GPT 模型、Mixtral 和 Claude 等 LLM 与外部应用程序、数据源和工具的通信方式」）
- 走客户端-服务器：服务器公开资源（数据）、提示（交互模板）、工具（可执行函数）；客户端（宿主程序或智能体）去用。（「MCP 基于客户端-服务器架构运行。它定义了不同元素——数据（称为资源）、交互模板（本质是提示）和可操作函数（称为工具）」）
- 书把 MCP 和「工具函数调用」拆开：后者是模型对一份预定义函数的一对一请求，格式随供应商变；MCP 是发现和通信的通用协议。（「工具函数调用可以被视为 LLM 对特定预定义工具或函数的直接请求」「这种过程通常是专有的，并且在不同的 LLM 提供商之间存在差异」）
- 发现是动态的：客户端向服务器要能力清单，而不是把工具名写死在这一轮对话里。（「支持动态发现可用工具。MCP 客户端可查询服务器以查看其提供能力」）
- 本地用 STDIO 上的 JSON-RPC；远程用可流式 HTTP 和 SSE。（「对于本地交互，使用基于 STDIO（标准输入/输出）的 JSON-RPC」「对于远程连接，利用 Web 友好协议如可流式 HTTP 和服务器发送事件（SSE）」）
- 协议还要规定鉴权和错误怎么传回模型，让模型换路。（「MCP 实现必须包含身份验证和授权」「协议必须定义如何将错误（如工具执行失败、服务器不可用、无效请求）传达回 LLM」）
- 书给的代码是 ADK 的 `MCPToolset`（连 `@modelcontextprotocol/server-filesystem`）和 FastMCP 的 `@mcp_server.tool`。（「`MCPToolset` 在 `LlmAgent` 对象的 `tools` 列表中实例化」「`@mcp_server.tool` 装饰器将此 Python 函数注册为 MCP 工具」）
- 书自己划了边界：工具种类固定时，直接函数调用就够；MCP 是为要互操作、要热插新能力的系统准备的。（「对于简单应用程序，特定工具就足够了；对于需要适应的复杂互联 AI 系统，像 MCP 这样的通用标准是必不可少的」）

## 结论
- 没做成
- 完成度：12
- 一句话：生产入口 `createExecutorDriver` → `createLlmControlDriver` 用 `ActionBuilder.buildDefaultActions` 写死动作表，不是 MCP；在 `chrome-extension/src/` 与 `pages/` 搜 `MCP`、`tools/list`、`FastMCP` 均为 0 命中。

## 对持节业务的意义
持节的用户操作是：把当前页上的事交出去，侧栏按发生的事往下长，交出能核对的结果。
MCP 要解决的是「任意模型连任意外部工具、热插新服务器、不重新发版」。
持节今天已经有工具面：Chrome 扩展进程里的 `ActionBuilder.buildDefaultActions`，由 `createLlmControlDriver` 在 `runObserveActLoop` 里按名字调用。
用户交「打开这个链接并点第一个结果」时，失败点是动作名不在 `ALLOWED_ACTIONS`、`kernel.act` 找不到 handler、或页面没变；不是 MCP 握手失败，也不是 `tools/list` 为空。
把持节再包一层 MCP 客户端，不会多交出一句能核对的结果，只会在扩展里再开一套协议。
只有一种产品选择才会用到本章：让 Cursor / Claude Code 当客户端、把这台已登录的 Chrome 暴露成远程 MCP（研究笔记里的 rtrvr 形态）。那是「给别人的智能体当浏览器用」，不是「用户把事交给持节侧栏」。

## 完成方案
Goal: 不引入 MCP 协议层；继续以 `ActionBuilder.buildDefaultActions` 为模型唯一动作面，经 `createLlmControlDriver` + `runObserveActLoop` 执行。
Hard bar: when I 在侧栏交出一句打开/点击任务, I see 侧栏长出打开或点击后的结果（或失败句），后台没有 MCP 服务器进程、没有 `tools/list` 请求。
改哪些现有文件: 不改。`factory.ts` 的生产分支保持 `createLlmControlDriver`；不要为本章新增 MCP 客户端或把扩展改成 MCP 服务器。
非目标: FastMCP、`MCPToolset`、STDIO MCP、把持节暴露给 Cursor/Claude Code、第二套 agent 树、把 `planner.ts` / `navigator.ts` 请回生产路径。
理由（书第 10 章自己的边界）：持节是固定浏览器动作集的单一扩展，「特定工具就足够了」。需要 MCP 的那一天，产品场景会先变成「外部智能体驱这台 Chrome」，再谈把现有 `Action` 包成服务器；现在不要为凑章去建。
