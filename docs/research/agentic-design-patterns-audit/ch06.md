# 第 6 章：规划（Planning）

## 书里的机制

- 规划是先从当前状态想出一串行动，再朝目标走（「构思一系列行动，从初始状态向目标状态推进」）。
- 用户只给目标和约束，不给做法；计划按这次请求当场生成，不是写死的脚本（「计划并非预先设定，而是根据请求动态生成」）。
- 第一份计划只是起点：场地满了、约束变了，就要记下新约束并改写计划（「初始计划仅是起点而非固定脚本」）。
- 若做法已经知道且可重复，应改用固定工作流，而不是每次都让模型自己发明路径（「将智能体限制在预先确定的固定工作流中会更有效」）。
- CrewAI 示例把任务写成两段：先列要点计划，再按计划写摘要（「1. 为主题…创建要点计划」「2. 根据您的计划撰写摘要」）。
- Google Deep Research 先把提示拆成多点研究计划，执行前交给用户审阅和修改（「呈现给用户审阅和修改」）。
- 执行中不是死跑预搜索：根据已收集信息找知识缺口、改查询、再搜（「根据收集的信息动态制定和优化查询」）。
- 框架里要用明确提示或任务设计逼出规划步骤，而不是只靠模型自己想起（「明确提示或设计任务以要求规划步骤」）。

```text
书：  用户目标 → 写出步骤计划 →（可选：人改）→ 按步执行 → 遇阻改写同一份计划
持节：用户那句 → refineMissionPlan 骨架 → runObserveActLoop 每步一个动作
               → onPlan 冻结验收条件 → 卡住只改 lastActionMemory，不改 phases
```

## 结论

- 部分做成
- 完成度：42
- 一句话：`TaskManager.start` 会跑 `refineMissionPlanFromInstruction`，`createLlmControlDriver` 每步用 `readCurrentMissionContext` 跟随这份骨架，但 `factory.ts` 的生产默认是 `createLlmControlDriver` → `runObserveActLoop`（每步一个 `action`），`PlannerAgent` 不在这条路上，也没有「先写出步骤再执行」或「执行前让用户改计划」。

## 对持节业务的意义

持节业务 = 用户把页面上的事交出去，侧栏按发生的事往下长，交出能核对的结果。

这一章若做成，改变的是交出去之后、第一次点击之前的那一下：模型先说出打算按什么顺序做，之后的搜索板和打开的页能对上这份顺序。

现在用户交一句「调研十家竞品并写成对比」，侧栏不会出现可改的步骤，只会开始搜、打开页；失败时看到「上一步未确认，正在恢复或换路」，而不是「计划已从竞品表改成先补来源」。

卡住或用户追加一句时，若仍不改写 `task.plan`，内部 `buildPlanMemory` 仍停在旧的 `阶段 N`，和实际打开的页对不上。

书里的 Deep Research「先给人改计划」和持节「不是逐步审批、不要预印栏目」冲突：缺的是工作流里的一次计划事件，不是再开一栏「目标」。

固定工作流已经在技能里部分承担「做法已知」的那一半；缺的是做法未知时先写步骤再走。

## 完成方案

- Goal: 生产路径在第一次页面动作前，把一份可跟随、可改写的步骤写进现有 `MissionPlan`，并在卡住或用户改方向时更新同一份对象。侧栏把这次写出当作工作流里发生的一件事，不恢复 `MissionPlanList` 栏目。
- Hard bar: when I 交出一句未手写 `1) 2) 3)` 的多步任务（例如「打开这两个站点，各记一条标题，再写一句对比」），I see 侧栏工作流里出现一次「打算：打开 A；打开 B；写出对比」，随后打开的页和交出的那句对得上这三步；when I 让它在错误页上卡住，I see 同一条计划被改写，而不是只重复上一次点击。
- 改哪些现有文件（不要新开第二套 agent 树）
  - `chrome-extension/src/background/agent/backends/control-policy.ts`：第一步允许模型给出 `plan_steps`（短标题列表），不是每步都重写。
  - `chrome-extension/src/background/task/mission-plan.ts`：一次把消毒后的标题写进 `phases`（仍上限 12、仍禁止把原文/密钥落盘）；`numberedStepSegments` 若用户已写编号则优先用用户原句片段。
  - `chrome-extension/src/background/task/manager.ts`：`onPlan` 或并列 hook 持久化这些标题；`followUp` 在 `direction_change` 时按新指令重建或改写 `task.plan`，不要只换 round。
  - `chrome-extension/src/background/agent/backends/control-llm.ts`：第一次 `decide` 在发出 `click_element` / `go_to_url` 之前写入计划；`onStuck` 除改 `lastActionMemory` 外，走同一条写回 `phases` 的路径。
  - `pages/side-panel/src/` 工作流事件（现有 Now / 页卡片通道）：把「打算：…」当成一条已发生的事插入，不预印栏目，不接回 `MissionPlanList`。
- 非目标:
  - 不把 `PlannerAgent` / `nano` / `executor.ts` 接回 `createExecutorDriver`。
  - 不加「计划批准后才跑」的闸门（持节不是逐步审批）。
  - 不恢复 `MissionPlanList`，不预印目标/现在/结果/做过。
  - 不把 `runSkillPlan` 当成通用规划器；技能路径继续走 `tryDecide`。
  - 不新开第二套 agent 树。
