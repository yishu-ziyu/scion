# 第 9 章：学习和适应（Learning and Adaptation）

## 书里的机制

- 学习是根据新经验和数据改思维方式、行动或知识；适应是学习之后别人能看见的行为或知识变化。（「智能体通过基于新经验和数据改变思维方式、行动或知识来实现学习和适应」；「"适应"是学习导致的智能体行为或知识的可见变化」）
- 没有从经验里学，预编程逻辑遇到没设计过的情况就会掉；标准解法是接上学习，让系统自己改知识和行为，而不是每次人手改程序。（「没有从经验中学习的能力，智能体无法随时间优化其策略」；「基于新数据和交互自主改进其知识和行为」）
- 书里列了几类学法：强化学习（试动作拿奖惩）、监督学习（标注映射）、无监督学习（未标注里找模式）、LLM 少样本/零样本（少量示例或明确指令就接新任务）、在线学习（持续改知识库）、基于记忆的学习（回忆过往经验改当前行动）。（「强化学习」「监督学习」「无监督学习」「基于大语言模型（LLM）的少样本/零样本学习」「在线学习」「基于记忆的学习」）
- PPO 用裁剪目标做小步策略更新；DPO 跳过奖励模型，直接用人类偏好对提高喜欢的回复、压低不喜欢的回复。（「近端策略优化（PPO）」；「直接偏好优化（DPO）」；「增加生成类似*偏好*响应的概率，减少生成类似*不受欢迎*响应的概率」）
- 知识库学习：把问题描述和成功解法存下来，决策时检索，套用成功模式、躲开已知坑（指向第 14 章 RAG）。（「维护问题描述和成功解决方案的动态知识库」）
- SICA 审自己的历史版本和基准分，选最高分版本改自己的代码，再测、再归档；另有异步监督者 LLM 看循环或停滞，必要时停掉。（「审查其历史版本档案及其在基准测试中的表现」；「直接修改代码库」；「异步监督者（另一个 LLM）监控 SICA 的行为」）
- AlphaEvolve / OpenEvolve 用 LLM + 自动评分 + 进化搜索发现或改算法，进化的是完整程序而不只是单次提示词。（「利用 LLM 的组合……自动化评估系统和进化算法框架」；「进化完整代码文件」）

## 结论

- 部分做成
- 完成度：30
- 一句话：当次任务里 `createLlmControlDriver` 会用 `lastActionMemory` / `buildLongHorizonContext` 改下一步，`TaskManager.saveSkill` 也能把已核对回执写成 `FavoriteSkill`，但 `runSkillPlan` / `canPromoteSkill` 在 `factory.ts` 与 `control-llm.ts` 零调用，`enableLearnedSkills` 默认 false，完成卡被禁止发 `save_skill`，上一次任务的轨迹不会改下一次独立任务。

## 对持节业务的意义

持节业务 = 用户把页面上的事交出去，侧栏按发生的事往下长，交出能核对的结果。

这一章该改的是「第二次交同类事时，还要不要从零摸索」。
今天第一次交「填表并提交」：侧栏按观察、点击、核对往下长，监督打回会写进当次 `lastActionMemory`，用户能看见「还没做完」。
同一条任务再补一句：`addFollowUp` 留在同一个 runner 里，记忆还在。
另开一件同类事：模型面前没有上次成功步骤，`eval-traces-v1` 也不回灌；完成卡不再画「保存为可再运行」（`docs/DEVLOG.md` 2026-08-18；`ui-acceptance.feature.md`）。
若 chrome.storage 里碰巧还有旧 `FavoriteSkill`，用户能在「可再运行」点「再跑一次」，侧栏出现「运行 Skill：…」再走同一条核对。
失败场景：昨天核对过的填表，今天再交一次，持节重新猜字段；用户找不到「存成下次可再用的模板」（`chat_skills_save` 只在 i18n，`.ts`/`.tsx` 零引用）。

## 完成方案

- Goal: 有核对回执之后，用户能从完成卡以外的入口把该轮存成 `FavoriteSkill`；下次在「可再运行」填新参数再跑时，冻结的是上次的核对标准，而不是空白任务。`TaskStatusCard` 仍然不画保存表。不把 PPO / SICA 自我改代码接到生产环。
- Hard bar: when I 把「把名字填进表并提交」做到侧栏交出已核对的那一句，再在历史收藏或书签区存成模板（完成卡上没有「保存为可再运行」），then I 在「可再运行」点「再跑一次」并填另一个名字，I see 新任务标题为「运行 Skill：…」，核对标准与上次回执同一套，且 `TaskManager.dispatch` 收到的是 `run_skill` 而不是空白 `start`。
- 改哪些现有文件（不要新开第二套 agent 树）
  - `pages/side-panel/src/SidePanel.tsx`：在 `handleSessionBookmark` 或书签区加一条「存为可再运行」，仅当当前任务 `status === 'completed'` 且本轮有 `receipt` 时 `sendTaskCommand({ type: 'save_skill', ... })`。不要改 `TaskStatusCard.tsx`（`ui-acceptance` 禁止）。
  - `chrome-extension/src/background/task/manager.ts`：`saveSkill` / `runSkill` 已接线；只补侧栏派发。
  - `packages/storage/lib/prompt/favorites.ts`：继续用 `createSkillDefinition` / `compileSkillTemplate`，不要另开配方库。
  - `pages/options/src/components/OverviewSettings.tsx`：文案改成与完成卡现状一致，或改成「从可再运行/历史收藏保存」。
  - 若以后要做书里的「从轨迹晋升」：在现有 `learned/plan.ts` 上写「已核对 attempts → SkillPlan」，`canPromoteSkill` 过了再让 `control-llm.ts` 的 `decide` 调 `runSkillPlan`；先把 `enableLearnedSkills` 接到这一条，而不是新开 agent。
- 非目标:
  - 不在完成卡上恢复「保存为可再运行」表单。
  - 不实现 PPO / DPO / 微调 / 奖励模型。
  - 不让扩展改自己的源码，不做版本档案选优，不接 OpenEvolve。
  - 不把 `SkillRuntime` 的写死技能算成学习。
  - 不复活 `planner.ts` / `navigator.ts` 当生产默认。
