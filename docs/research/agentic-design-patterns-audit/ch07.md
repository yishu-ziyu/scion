# 第 7 章：多智能体协作（Multi-Agent Collaboration）

## 书里的机制
- 复杂任务拆成子问题，每个子问题交给有对应工具或推理能力的专门智能体，而不是一个单体包办。（「然后将每个子问题分配给拥有最适合该任务的特定工具、数据访问或推理能力的智能体」）
- 协作靠智能体之间的通信：要有约定好的交换格式，用来传数据、派活、对齐行动。（「这需要标准化的通信协议和共享本体，允许智能体交换数据、分配任务并协调其行动」）
- 顺序交接：一个智能体做完，把输出交给下一个智能体做流水线下一步。（「顺序交接：一个智能体处理任务并将其输出传递给另一个智能体」）
- 并行处理：多个智能体同时做问题的不同部分，再合并结果。（「并行处理：多个智能体同时处理问题的不同部分，然后它们的结果稍后被组合」）
- 辩论与共识：持不同观点的智能体讨论后再决策。（「辩论与共识：……通过讨论评估选项，最终达成共识」）
- 层次结构 / 监督者：管理者按工具或能力把任务委托给工作智能体，再综合结果。（「层次结构：管理者智能体根据工具访问或插件能力动态将任务委托给工作智能体」）
- 批评者-审查者：一个智能体先给出计划或答案，另一组智能体按正确性与目标核对，原作者再改。（「批评者-审查者：一个智能体生成初始输出……第二组智能体批判性地评估此输出」）
- 实操里用 CrewAI 的 `Agent` + `Task` + `Crew(process=Process.sequential)`，或 Google ADK 的 `sub_agents`、`SequentialAgent`、`ParallelAgent`、`AgentTool`。（「然后将这些智能体和任务组装成一个团队，指定顺序流程」；「greeter 和 task_doer 作为子智能体添加到 coordinator」）

## 结论
- 部分做成
- 完成度：32
- 一句话：生产路径只有 `createLlmControlDriver` 里的 `settleProposedDone` 会对 `supervisorLlm.invoke` 做第二次模型调用；`factory.ts` 的 `createExecutorDriver` 在默认 `control` 下不引用 `PlannerAgent` / `NavigatorAgent`，`SkillRuntime.tryDecide` 的 `skill.run` 也没有 `invoke`。

## 对持节业务的意义
用户把页面上的事交出去之后，真正会碰到的第二角色只有「核对做完没有」。
工作环或技能一说做完，`settleProposedDone` 先发「正在核对页面上的结果」，对不上就打回继续点，侧栏按这件事往下长，而不是立刻「这件事已经做完了」。
这改变的是交结果那一次，不是拆成研究员/作家两条线。
并行开多个网址（`openIndependentTabs`）只改变标签，不改变谁在做。
`SkillRuntime.tryDecide` 失败就回落到工人 `llm.invoke`，用户看不到第二个智能体接手。
把后端切回 `nano` 才会再跑 `PlannerAgent` + `NavigatorAgent`；默认 `control` 下设置页的「制定并调整策略」不会发生。

## 完成方案
- Goal: 默认 `control` 路径上，用户能核对的「第二角色」仍然只活在 `createLlmControlDriver` 的第二次 `invoke` 里（现有监督已接线）；若要对齐本章其余形态，也只在同一文件里加有独立 system prompt、侧栏能长出那一句的第二次调用，不复活 `Executor`。
- Hard bar: when I 把一件打开/抽取类的事交出去、工作环声称做完，I see 侧栏出现「正在核对页面上的结果」；when 当前页对不上用户那句，I see 「还没做完：…」且任务仍在点，不会交假完成。
- 改哪些现有文件（不要新开第二套 agent 树）：`chrome-extension/src/background/agent/backends/control-llm.ts`（继续从 `settleProposedDone` 长，不从 `factory.ts` 接回 `agents/planner.ts`）；`chrome-extension/src/background/agent/backends/control-supervise.ts`（通信仍是 JSON 裁决）；`pages/side-panel/src/presentation/humanize-message.ts`（只露出中文，不露出 Planner/Navigator/Validator 名称）。设置页 `AgentNameEnum.Planner` 若生产不用，不要为了本章去接线。
- 非目标: 不引入 CrewAI / Google ADK；不把 `SkillRuntime.tryDecide` 算成智能体；不把 `BrowserContext.openIndependentTabs` 扩成并行智能体；不为辩论/专家团队新开目录。
