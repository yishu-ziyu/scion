# 第 15 章：智能体间通信（Inter-Agent Communication (A2A)）

## 书里的机制
- 单个智能体不够时，A2A 让可能基于不同框架的智能体协作：协调、委派任务、交换信息。（「使得不同 AI 智能体（可能基于不同框架构建）能够进行有效协作」）
- 开放标准面向跨框架互操作（LangGraph、CrewAI、Google ADK），不是同一进程里两次模型调用。（「实现不同 AI 智能体框架间通信与协作的开放标准」）
- 三方角色：用户发起请求；A2A 客户端代表用户去请求；A2A 服务器是提供 HTTP 端点的远程智能体，内部对客户端不透明。（「A2A 客户端（客户端 Agent）」「A2A 服务器（远程 Agent）」「以“不透明”方式运行」）
- 远程智能体用 Agent 卡片当数字身份：JSON 里写 name、url、version、capabilities、authentication、skills。（「Agent 的数字身份由其智能体卡片定义，通常是 JSON 文件」）
- 发现卡片有三条路：标准 URI（`/.well-known/agent.json`）、精选注册表、私下直接配置。（「标准 URI：Agent 在标准化路径（如 /.well-known/agent.json）托管其智能体卡片」）
- 通信绕异步任务转：任务有唯一 ID 和状态；消息带属性和一个或多个部分；产出叫工件；传输是 HTTP(S) 上的 JSON-RPC 2.0；相关任务用服务器发的 `contextId` 分组。（「所有通信都通过 HTTP(S) 进行，使用 JSON-RPC 2.0 协议作为有效载荷」）
- 交互四种：同步 `sendTask`、异步轮询、SSE `sendTaskSubscribe`、webhook 推送；卡片声明是否支持流式或推送。（「同步请求使用 sendTask 方法」「流式请求使用 sendTaskSubscribe 方法」）
- 安全写在协议里：双向 TLS、审计日志、卡片声明鉴权方案、OAuth / API 密钥走 HTTP 头。书把 A2A 和 MCP 拆开：MCP 连工具与数据，A2A 做智能体发现与委派。（「MCP 专注于为智能体提供上下文及其与外部数据和工具的交互，而 A2A 则促进智能体间发现和通信」）

```text
书：  用户 → A2A 客户端智能体 --HTTP JSON-RPC--> 远程 A2A 服务器智能体（先读 Agent 卡片）
持节：用户 → 侧栏 chrome.runtime.connect('side-panel-connection')
            → service worker TaskManager.dispatch
            → createExecutorDriver → createLlmControlDriver → runObserveActLoop
```

## 结论
- 没做成
- 完成度：8
- 一句话：`chrome-extension/`、`pages/`、`packages/` 搜 `A2A`、`AgentCard`、`sendTaskSubscribe`、`well-known/agent` 均为 0 命中；`chrome-extension/src/background/index.ts` 的 `chrome.runtime.onConnect` 只把 `side-panel-connection` 接到 `TaskManager.dispatch`，不是两个智能体按协议交换消息。

## 对持节业务的意义
持节业务 = 用户把页面上的事交出去，侧栏按发生的事往下长，交出能核对的结果。
本章要改的是「另一个智能体（可能别的框架、别的进程）按协议发现持节、把任务派过来」或「持节按卡片去调远程日历/天气智能体」。
今天用户交「打开这个链接并点第一个结果」时，话只进 `TaskManager.dispatch`，执行只进 `createLlmControlDriver` + `runObserveActLoop`。
侧栏断开或 service worker 重启，用户看见的是任务中断或重连，不是 A2A 客户端找不到 Agent 卡片。
`settleProposedDone` 改变的是交结果那一次（页上对得上才结束），不是把活委派给远程智能体。
为本章去挂 `/.well-known/agent.json` 或 `A2AStarletteApplication`，不会让侧栏多交出一句能核对的结果，只会多开一条给外部客户端用的入口。

## 完成方案
- Goal: 不引入 A2A 协议层。生产路径保持 `createExecutorDriver` → `createLlmControlDriver` → `runObserveActLoop`；侧栏继续只通过 `side-panel-connection` 把 `TaskCommand` 交给 `TaskManager.dispatch`。
- Hard bar: when I 在侧栏交出一句打开或点击任务, I see 侧栏长出打开或点击后的结果（或失败句）；后台没有监听 A2A HTTP 的端点、没有 Agent 卡片、没有第二个智能体进程。
- 改哪些现有文件（不要新开第二套 agent 树）：不改。不要把 `chrome.runtime.onConnect` 扩成 A2A 服务器；不要为 `sendTaskCommand` 这个本地函数名去实现 JSON-RPC `sendTask`。
- 非目标: `AgentCard`、`/.well-known/agent.json`、`sendTaskSubscribe`、mTLS、把持节暴露给 Cursor / 其他浏览器智能体、复活 `planner.ts` / `navigator.ts`、把 `supervisorLlm.invoke` 包成远程智能体。
- 理由：书自己的「实践建议」是「当您需要协调两个或多个 AI 智能体协作时使用此模式」。持节默认是一个扩展里的一条任务环。需要 A2A 的那天，产品场景会先变成「外部智能体驱这台已登录的 Chrome」，再谈卡片和 HTTP；现在不要为凑章去建。
