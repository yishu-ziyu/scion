# 第 21 章：探索和发现（Exploration and Discovery）

## 书里的机制
- 探索和发现是主动走进陌生领域、试新方法、生成新理解，不是在已经圈好的方案空间里做优化。（「主动进入陌生领域、尝试新方法并生成新知识或理解」「不同于被动行为或在预定义解决方案空间内的优化」）
- 适用场景是开放、复杂、还在变的领域：科学研究、市场趋势、安全探测、创意组合；目标是找出「未知的未知因素」，不是把已知流程再拧紧一点。（「识别"未知的未知因素"」「而不仅仅是优化已知过程」）
- Google 协同科学家用多智能体模拟科研：生成假设、反思评审、Elo 锦标赛排名、进化改写、邻近度聚类、元审查反馈。（「生成智能体」「反思智能体」「排名智能体」「采用基于 Elo 的锦标赛机制」「进化智能体」「邻近度智能体」「元审查智能体」）
- 运营环是「生成、辩论和进化」，并靠加测试时计算把假设质量抬高。（「迭代"生成、辩论和进化"方法」「测试时计算扩展」）
- Agent Laboratory 把研究拆成文献综述、实验、报告撰写，再用 AgentRxiv 把产出存起来给后续智能体接着用。（「文献综述」「实验」「报告撰写」「AgentRxiv」）
- 判断用三方审稿：三个不同提示词的审稿人各自打分，再拼成一份审查。（「三方智能体判断机制」「审稿人 #1」「审稿人 #2」「审稿人 #3」）
- 人还在环里：科学家用自然语言带路；研究目标进门要做安全审查，避免危险课题。（「科学家在环」「所有研究目标在输入时都会进行安全审查」）
- 参考文献点明探索-利用困境：在不确定下既要试新选项，也要沿用已经有效的路。（「Exploration-Exploitation Dilemma」）

## 结论
- 部分做成
- 完成度：40

## 对持节业务的意义

持节业务 = 用户把页面上的事交出去，侧栏按发生的事往下长，交出能核对的结果。

```mermaid
sequenceDiagram
  participant User as 侧栏那一句
  participant Gate as instructionLooksLikeResearch
  participant Loop as runObserveActLoop
  participant Search as search_google / collectSearchFindings
  participant Open as openAndDescribeIndependentPages
  participant Keep as recordEvidence
  participant UI as WorkStream
  User->>Loop: createExecutorDriver → createLlmControlDriver
  Loop->>Gate: 是否调研句
  Gate-->>Loop: 是才拼 R1–R6
  Loop->>Search: 没有现成 URL 则 Google
  Search-->>UI: 搜索板 + 最多 6 条命中
  Search->>Open: 仅当原句要打开前 N 条
  Open-->>UI: 打开的页卡片
  alt 调研句且已打开真页
    Loop->>Keep: 摘要页拒收；正文对得上才入库
  end
  Loop-->>User: 可对页核对的那一句
```

用户说「搜清程极智黑客松看报名要求」时，改的是：会不会先出现搜索板，会不会打开真实报名页，最后一句能不能对上打开页上的字。
用户没写「打开前 N 条」时，并排试选项不会发生；模型可以自己点一条，这是提示词运气，不是 `urlsForIndependentOpen` 的确定性路径。
调研句（证据空间 / 建立能力地图 / 飞书写入 / 用户讨论配额）才会走 `record_evidence`；普通「搜一下」不会在侧栏留下证据台账。
失败场景：停在 Google 摘要上把截止时间写进结果，监督若只看到搜索页标题也可能放行；用户对页核对时对不上报名页原文。
`discoverSkills` / `searchAndOpenSkill` 不是本章的发现：它们只接已经写死的维基和 example.com 捷径。

## 完成方案

- Goal: 开放式查找在生产路径 `createLlmControlDriver` 上会进入搜索页，并把 `collectSearchFindings` 的真实结果打开至少一条；侧栏搜索板长出查询词和可点命中，工作流再长出打开的页；调研句才调用 `record_evidence`，搜索摘要不能入库。
- Hard bar: when I do 「搜清程极智黑客松，看报名要求和截止时间」（不写「打开前 N 条」）, I see 侧栏「已完成网页搜索」、至少一条可点命中、一张打开的报名页卡片，以及一句能对上该页原文的结果；when I do 一条 `instructionLooksLikeResearch` 为真的调研句并停在 Google 结果页就 `record_evidence`, I see 动作结果是「current page is search results」且证据空间条数不增加。
- 改哪些现有文件（不要新开第二套 agent 树）
  - `chrome-extension/src/background/task/independent-urls.ts`：`urlsForIndependentOpen` / `instructionWantsOpenedSearchResults` 在开放式查找（没有现成 URL、当前页是 SERP）时也允许打开前几条命中，而不是只认「打开前 N 条」。
  - `chrome-extension/src/background/agent/backends/control-policy.ts`：默认 `CONTROL_SYSTEM_PROMPT_BODY` 写明：目标还没有具体 URL 时用 `search_google`；停在结果页时先打开真实来源再写 `observation`，不要用摘要交差。
  - `chrome-extension/src/background/agent/backends/control-llm.ts`：观察步已有 `collectSearchFindings` + `openAndDescribeIndependentPages`；打开后把已打开页写进 `lastActionMemory`（现成 `independentPagesMemory` 未接线）。
  - `pages/side-panel/src/presentation/work-stream.ts`：搜索板已够用；不要把 `record_evidence` 从 `HIDDEN_ACTIONS` 拿出来当聊天气泡。若要让用户看见「留下了什么」，用 `deriveTaskProgressView` 把 `EvidenceSpace.records` 投影成来源列表，而不是新开一栏。
- 非目标:
  - 不实现 Elo 锦标赛、生成/反思/排名/进化/邻近度/元审查智能体、AgentRxiv、Python 实验、LaTeX 报告。
  - 不把 `planner.ts` / `navigator.ts` 请回生产路径，不新开第二套 agent 树。
  - 不把 `discoverSkills` 改造成「发现未知方法」；它继续只匹配原子捷径。
