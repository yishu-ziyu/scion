# 第 8 章：记忆管理（Memory Management）

## 书里的机制

- 短期记忆就是当前这次交互里还在用的信息，对大模型来说主要住在上下文窗口：最近消息、回复、工具结果、反思；窗口有限，会话结束就丢。（「短期记忆主要存在于上下文窗口中」「该窗口包含最近消息、智能体回复、工具使用结果」「会话结束即丢失」）
- 窗口满了要在有限空间里留最相关的：总结旧对话，或只突出关键细节；更长的窗口只是把短期容量变大，仍不是持久记忆。（「可能通过总结旧对话片段或突出关键细节」「具有"长上下文"窗口的模型只是扩展了短期记忆容量」）
- 长期记忆放在智能体环境之外，常见于数据库、知识图谱或向量库；需要时查出来，再塞回短期上下文。（「数据通常存储在智能体环境之外」「检索相关数据并集成到短期上下文中」）
- Google ADK 拆成三块：Session 是一条聊天线程（事件 + 临时 State），Memory 是可搜索的过往/外部库；SessionService 管线程生命周期，MemoryService 管长期存取。（「Session（会话）：独立的聊天线程」「Memory（记忆）：……可搜索存储库」「SessionService 管理聊天线程」「MemoryService 监督长期知识」）
- State 是当前线程上的键值草稿本；`user:` / `app:` / `temp:` 前缀决定归属和是否持久；应通过 `append_event` 的 `state_delta` 或 `output_key` 改，不要直接改字典。（「session.state 存储和更新与活动聊天相关的动态数据点」「user: 前缀将数据与跨所有会话的用户 ID 关联」「应通过……EventActions.state_delta 或 output_key 更新状态」）
- MemoryService 的标准动作是 `add_session_to_memory` 写入、`search_memory` 取回；生产上常接到向量 RAG。（「add_session_to_memory」「search_memory」「VertexAiRagMemoryService」）
- LangChain 的 `ConversationBufferMemory` 把本线程对话自动注入提示；LangGraph 把长期记忆分成语义事实、情景经历、可更新的程序规则，放在带命名空间的 Store 里。（「保存对话的缓冲区并使其可用于您的提示词」「语义记忆：记住事实」「情景记忆：记住经历」「程序记忆：记住规则」）
- Vertex Memory Bank 异步从对话里抽出事实和用户偏好，按用户范围存，新会话开始时再按完整数据或嵌入相似度调回来。（「异步分析对话历史，提取关键事实和用户偏好」「通过完整数据调用或嵌入相似度搜索检索相关记忆」）

## 结论

- 部分做成
- 完成度：48
- 一句话：生产路径 `createLlmControlDriver` 每步用 `buildLongHorizonContext` / `buildControlUserPrompt` 把当前页、压缩轨迹、计划、`lastActionMemory` 和 `formatVerifiedPagesForPrompt` 写进当轮上下文，`saveTask` / `chatHistoryStore.addMessage` 也把任务和侧栏对话落在 `chrome.storage.local`；仓库没有 `search_memory` / `add_session_to_memory` / embedding，跨任务不会自动把上次偏好或回执检索进提示。

## 对持节业务的意义

持节业务 = 用户把页面上的事交出去，侧栏按发生的事往下长，交出能核对的结果。

交出去之后，真正决定下一拍点哪里的，是当轮 `buildControlUserPrompt` 里的当前页、压缩轨迹、计划和上次动作，不是侧栏里已经长出来的全部聊天字。
同一条任务里补一句（follow_up），`addFollowUp` 会把新句子拼进还在跑的 instruction，侧栏继续往下长。
任务被 `persistVerifiedReceipt` 标成完成后，driver 常被 `stopTaskRuntime` 拆掉：页标题和证据还在 `TaskSession` / `EvidenceSpace` 里，但闭包里的轨迹和 `lastActionMemory` 没了。
用户点「加载历史」只能把旧侧栏铺回来给自己看；新交出去的事不会自动检索上周那次回执。
失败场景：调研记过一条 Reddit 原话，扩展重启后再说「接着上次的表」，模型面前只有新的当前页，会重搜或编；侧栏结果对不上那条 URL。

## 完成方案

- Goal: 当本机已有过往 `EvidenceSpace.records` 或已核对回执时，新任务第一次 `decide` 就能把相关来源 URL + 原文/观察写进 `buildControlUserPrompt`，不必等模型自己想起调 `inspect_evidence_space`，也不新开第二套 agent。
- Hard bar:（when I do X, I see Y）先完成一次记过 `record_evidence` 的调研任务，再新开侧栏说「按上次记下的用户原话继续」。下一轮发给模型的 user 提示里必须出现那条 `raw_basis` 和来源 URL；侧栏结果下列出该 URL。模型不调用 `inspect_evidence_space` 也要成立。
- 改哪些现有文件（不要新开第二套 agent 树）
  - `packages/storage/lib/task/evidence-space.ts`：在现有 `searchableEvidenceText` / 按 `taskId` 分桶之上，加一个可按查询过滤最近若干任务记录的纯函数；不要上向量库。
  - `chrome-extension/src/background/task/manager.ts`：`persistVerifiedReceipt` 成功时写一条可检索的短事实（goal + 来源 URL），仍走现有 `chrome.storage.local`。
  - `chrome-extension/src/background/agent/backends/control-llm.ts`：`decide` 里把检索块注入 `buildControlUserPrompt`；默认观察仍走当前页。
  - `pages/side-panel/src/presentation/work-stream.ts`：结果下列出本次用到的证据/回执 URL，不把检索做成新栏目。
- 非目标:
  - 不引入 Vertex Memory Bank、嵌入模型、向量数据库。
  - 不把 `MessageManager` / `cutMessages` 接回生产 control 路径。
  - 不打开 `enableLearnedSkills`、不把 `runSkillPlan` 变成第二套运行时。
  - 不复活 `planner.ts` / `navigator.ts` 当记忆层。
  - 不把侧栏聊天全文无裁剪塞进每一轮提示。
